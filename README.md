# Circle Raider — модульная версия на Godot

Изометрический рогалик для Godot 4.7. Браузерная версия сохранена в ветке `circle-raider`, а эта версия находится в ветке `godot-port`.

В проекте нет обязательных внешних изображений: герой, оружие, противники, предметы и локация рисуются средствами Godot из кода. Благодаря этому каждую механику можно менять независимо.

## Быстрый запуск

1. Запустите Godot 4.7.
2. В менеджере проектов нажмите **Import**.
3. Выберите `project.godot` из корня репозитория.
4. Откройте проект.
5. Нажмите `F6` или кнопку запуска проекта.

Управление:

- `WASD` — движение;
- мышь — направление взгляда и оружия;
- левая кнопка мыши — удар мечом;
- правая кнопка мыши — применить выбранное заклинание.

## Как устроен игровой цикл

```text
project.godot
└── scenes/main.tscn
    └── scripts/main.gd
        ├── Location — рисует только пол и границу
        ├── WorldRoot (Y-sort)
        │   ├── герой
        │   ├── враги
        │   ├── кусты, бочки и деревья
        │   └── опыт и бутылки
        ├── Projectiles — стрелы и магия
        ├── WaveManager — волны и лимит врагов
        └── GameUI — меню, HUD и экраны завершения
```

Герой хранит игровые координаты в `world_position`. Файл `iso_math.gd` переводит их в экранные изометрические координаты. Поэтому логика движения и дистанций остаётся простой двухмерной, а изображение выглядит изометрическим.

## Корневые файлы

### `project.godot`

Главная конфигурация Godot.

Что здесь находится:

- имя проекта — `config/name`;
- стартовая сцена — `run/main_scene`;
- разрешение — параметры `window/size/*`;
- фиксированная частота симуляции — `physics/common/physics_ticks_per_second = 60`;
- действия управления — раздел `[input]`;
- названия физических слоёв — `[layer_names]`;
- режим рендера — `[rendering]`.

Для переназначения клавиш удобнее открыть **Project → Project Settings → Input Map**, а не редактировать сериализованные `InputEvent` вручную.

Для магии используется действие `cast_magic`, назначенное на правую кнопку мыши. Меч использует отдельное действие `attack`, поэтому обе атаки можно переназначать независимо.

### `.gitignore`

Исключает из Git локальный кэш Godot `.godot/`, папки сборок, настройки редакторов и вложенный тестовый проект `warrioir-/`.

Файлы исходного кода и `.gd.uid` игнорировать не нужно.

### `README.md`

Этот документ. Его изменение не влияет на игру.

### `resources/world_config.tres`

Единый редактируемый ресурс баланса мира. Он хранит `world_limit`, безопасный отступ появления, интервалы размещения пропсов, настройки магнита опыта и основные параметры волн. Скрипт ресурса находится в `scripts/config/world_config.gd`. Изменяйте значения в `.tres` через Inspector или текстом — игрок, враги, локация, предметы и `WaveManager` получают один экземпляр этого ресурса из `main.gd`.

## Сцены

Сцены хранят узлы Godot и подключают соответствующие скрипты.

### `scenes/main.tscn`

Стартовая сцена. Содержит корневой `Node2D` со скриптом `scripts/main.gd`.

Содержит постоянные контейнеры `FloorLayer`, `WorldRoot` и `Projectiles`. Главный скрипт создаёт runtime-объекты уже внутри нужного слоя.

### `scenes/player/player.tscn`

Отдельная сцена героя. Содержит постоянные узлы `Movement`, `Attack`, `Magic`, `Camera`, `VisualRoot` и `Hurtbox/CollisionShape2D`. Компоненты можно выбирать и настраивать отдельно в дереве сцены.

`player.gd` связывает готовые узлы через `@onready`, но больше не создаёт их кодом и не рисует модель. Граница перемещения приходит из `resources/world_config.tres`.

### `scenes/world/location.tscn`

Сцена локации. Подключает `scripts/world/location.gd`.

Через Inspector можно менять:

- `world_limit` — половина ширины и высоты мира;
- `tile_size` — размер одной плитки изометрического пола.

### `scenes/enemies/brawler_enemy.tscn`

Сцена базового серого бойца с двумя кулаками. Подключает `brawler_enemy.gd`.

### `scenes/enemies/melee_enemy.tscn`

Сцена зелёного мечника. Подключает `melee_enemy.gd`.

### `scenes/enemies/shooter_enemy.tscn`

Сцена красного стрелка. Подключает `shooter_enemy.gd`.

### `scenes/enemies/lancer_enemy.tscn`

Сцена ромба-копейщика. Подключает `lancer_enemy.gd`.

### `scenes/enemies/lightning_mage.tscn`

Сцена синего мага молнии. Подключает `lightning_mage.gd`; появляется начиная со второй волны.

### `scenes/enemies/fire_mage.tscn`

Сцена красного мага огня. Подключает `fire_mage.gd`; появляется начиная с пятой волны.

### `scenes/enemies/boss_enemy.tscn`

Сцена большого босса с топором. Подключает `boss_enemy.gd`.

Каждая сцена врага дополнительно содержит собственные узлы `VisualRoot` и `Hurtbox/CollisionShape2D`. Поведенческий скрипт хранит характеристики и AI, `enemy_visual.gd` отвечает только за внешний вид, а `EntityHurtbox` синхронизирует форму с `collision_radius` при входе в дерево.

Параметры врагов пока задаются в `_init()` их скриптов. Чтобы редактировать их через Inspector, можно заменить нужную переменную в `enemy_base.gd` или дочернем скрипте на `@export var` и сохранить значение в сцене.

## Главная сборка

### `scripts/main.gd`

Связывает все игровые системы. Здесь нет подробной логики отдельного врага или меча — только создание объектов и передача событий.

Основные части:

- константы `*_SCENE` загружают сцены игрока, локации и противников;
- `_ready()` создаёт системы, общий `WorldRoot` с Y-сортировкой и соединяет сигналы;
- `_start_run()` начинает новый забег;
- `_clear_runtime_nodes()` удаляет старых врагов, снаряды и предметы при перезапуске;
- `_spawn_enemy()` выбирает сцену из словаря `enemy_scenes` по безопасному `StringName`;
- `_find_spawn_position()` делает до 16 попыток найти удалённую от игрока точку внутри карты;
- `_spawn_projectile()` создаёт снаряд стрелка;
- `_spawn_player_magic()` создаёт молнию или фаербол героя;
- `_spawn_enemy_spell()` создаёт заклинание вражеского мага;
- `_spawn_potion()` создаёт бутылку лечения;
- `_spawn_experience()` делит опыт на несколько магнитящихся сфер;
- `_on_enemy_died()` выдаёт опыт и распознаёт смерть босса;
- `_start_boss()` убирает обычных врагов после седьмой волны;
- `_on_level_up()` добавляет каждый новый уровень в `pending_level_ups`;
- `_show_next_level_up()` последовательно показывает накопленные панели и фильтрует варианты;
- `available_upgrade_choices()` возвращает только доступные на текущий момент усиления;
- `_apply_upgrade()` применяет обычное усиление или передаёт выбор в `PlayerMagic`;
- `_on_magic_changed()` обновляет название активной магии в HUD;
- `_finish_run()` единообразно завершает победу и поражение, удаляя все игровые объекты.

Часто изменяемые значения:

- `620.0` в `_spawn_enemy()` — дистанция появления обычного врага от героя;
- `520.0` — дистанция появления босса;
- `safe_spawn_margin` в `world_config.tres` — внутренний отступ точки появления от границы карты;
- `28` в `_spawn_potion()` — количество восстанавливаемого здоровья;
- `10` в `_spawn_experience()` — максимальная ценность одной сферы опыта.

`WorldState` хранит типизированные реестры живых врагов, вражеских снарядов и разрушаемых объектов. Они используются для лимита появления, попаданий меча и магических снарядов без покадровых `get_nodes_in_group()`. Чтобы зарегистрировать новый тип врага, добавьте идентификатор в `GameIds`, сцену в константы и пару идентификатор–сцена в `enemy_scenes`.

### `scripts/world/world_state.gd`

Центральный runtime-реестр боя:

- `_enemies`, `_enemy_projectiles` и `_destructibles` — закрытые изменяемые коллекции самого реестра;
- `enemy_snapshot()` — типизированная копия всех активных врагов;
- `enemy_projectile_snapshot()` — копия стрел и вражеской магии с контрактом отбивания;
- `destructible_snapshot()` — копия живых кустов и бочек;
- методы `register_*()` подключаются к `tree_exiting`, поэтому освобождённый узел автоматически удаляется из коллекции;
- `replace_destructibles()` обновляет набор после регенерации локации;
- `clear_runtime()` очищает врагов и снаряды при завершении или перезапуске забега.

Боевые системы всегда обходят snapshot. Если попадание убивает цель и обработчик смерти сразу изменяет реестр, текущий цикл продолжает работать со стабильной копией и не пропускает следующего врага. Изменение или очистка полученного массива также не влияет на внутреннее состояние `WorldState`.

### `scripts/core/game_ids.gd`

Единое место для `StringName`-идентификаторов врагов, заклинаний, предметов, объектов окружения и улучшений. Используйте эти константы вместо повторения строк: опечатка в неизвестном идентификаторе теперь вызывает `push_error()`, а не создаёт молча другой тип врага.

## Изометрия

### `scripts/core/iso_math.gd`

Содержит только преобразование координат.

- `X_SCALE = 1.18` отвечает за горизонтальное растяжение ромбической сетки;
- `Y_SCALE = 0.56` отвечает за вертикальное сжатие;
- `world_to_screen()` переводит координаты мира в позицию на экране;
- `screen_to_world()` выполняет обратное преобразование;
- `world_direction_from_screen()` переводит направление `WASD` или мыши в направление мира;
- `screen_angle()` вычисляет угол для отрисовки оружия.

Если изменить `X_SCALE` или `Y_SCALE`, изменится наклон всей изометрии. Эти значения должны применяться ко всем объектам через данный файл; не дублируйте формулу в других скриптах.

### `scripts/core/collision_math.gd`

Содержит swept collision для быстрых снарядов. `segment_circle_hit_fraction()` проверяет весь отрезок между прошлой и новой позицией и возвращает первое место попадания от `0.0` до `1.0`. Благодаря этому стрела или молния не перепрыгивает через небольшую цель между двумя physics tick.

## Герой

### `scripts/player/player.gd`

Хранит состояние героя и рисует его модель.

Основные переменные:

- `world_limit` — предел перемещения, который при создании передаётся из `GameLocation`;
- `visual_radius = 22.0` — стартовый размер нарисованного круга;
- `collision_radius = 22.0` — world-space радиус попаданий и подбора;
- `max_health = 100.0` — максимальное здоровье;
- `health = 100.0` — текущее здоровье;
- `experience_required = 100` — опыт для первого повышения уровня;
- `invulnerability` — оставшееся время неуязвимости после получения урона.

Важные методы:

- `_physics_process()` получает снимок ввода, обновляет направление мыши, движение, атаку и магию с фиксированным шагом;
- `take_damage()` уменьшает здоровье и включает `0.45` секунды неуязвимости;
- `heal()` лечит героя;
- `add_experience()` повышает уровень и пересчитывает следующий порог по формуле `experience_required * 1.24 + 18`;
- `upgrade_speed()` увеличивает скорость на `12%`;
- `upgrade_vitality()` добавляет `25` здоровья и увеличивает радиус на `2.5`;
- `reset_run()` возвращает стартовые параметры;
- `refresh_visual()` запрашивает перерисовку дочернего `VisualRoot`;
- изменение живучести синхронно меняет радиус `Hurtbox`.

### `scripts/player/player_visual.gd`

Чисто визуальный компонент героя. `_draw()` рисует тело и направление взгляда, `_draw_swing_trail()` строит след клинка, а `_draw_sword()` выбирает размеры модели по состоянию `PlayerAttack`. Здесь можно менять цвета и форму героя, не затрагивая движение или боевые расчёты.

### `scripts/entities/entity_hurtbox.gd`

Общий контракт узла `Hurtbox` для героя и врагов. `set_collision_radius()` обновляет `CircleShape2D`; у героя он вызывается также после усиления живучести. `visual_radius` никогда не читается боевой логикой, поэтому изменение модели не меняет область попадания.

Важно: если меняете стартовое здоровье или размер, обновите те же значения внутри `reset_run()`, иначе после перезапуска забега вернутся старые числа.

### `scripts/player/player_movement.gd`

Отвечает только за движение.

Экспортируемые параметры:

- `speed = 195.0` — максимальная скорость;
- `acceleration = 1250.0` — скорость разгона;
- `deceleration = 1550.0` — скорость остановки.

`step()` получает `WASD` из `InputState`, переводит экранное направление в координаты мира, плавно изменяет `velocity` и ограничивает позицию границами карты.

### `scripts/player/input_state.gd`

Снимает состояние `WASD`, мыши, ЛКМ и ПКМ один раз в начале physics tick. Игровая логика использует сохранённые `movement_screen`, `aim_world`, `attack_pressed` и `magic_pressed`, а не опрашивает `Input` из разных компонентов в разное время.

Примеры:

- более тяжёлый герой: уменьшить `acceleration` до `700`, `deceleration` до `900`;
- более отзывчивое движение: увеличить оба значения до `2200`;
- ускорить героя: увеличить `speed`.

Если меняете стартовую `speed`, обновите значение `195.0` в `PlayerHero.reset_run()`.

### `scripts/player/player_attack.gd`

Отвечает только за атаку и попадания.

Основные параметры:

- `SWEEP_START = -1.22` — начало дуги удара относительно направления мыши;
- `SWEEP_END = 1.04` — конец дуги;
- `damage = 34.0` — базовый урон;
- `attack_reach = 91.0` — внешний радиус удара в мировых единицах;
- `attack_half_width = 7.0` — физическая половина ширины клинка;
- `visual_sword_length = 91.0` — только длина нарисованной модели;
- `cooldown_duration = 0.36` — пауза между ударами;
- `swing_duration = 0.28` — длительность анимации.

Направление удара чередуется автоматически. `next_swing_direction` хранит направление следующей атаки: первый замах идёт слева направо, второй справа налево. Методы `swing_start_offset()` и `swing_end_offset()` меняют начало и конец анимации местами. `swing_aim_direction` фиксирует направление мыши на короткое время замаха, чтобы модель и зона попадания двигались вместе.

Как изменить размах:

- сделать шире — уменьшить `SWEEP_START` и увеличить `SWEEP_END`;
- сделать уже — приблизить оба значения к нулю;
- сместить удар в одну сторону — одновременно сдвинуть оба значения.

`point_in_blade_sweep()` передаёт мировую позицию, направление, дальность и collision radius в `AttackShape`. `IsoMath`, камера, экранные углы и размеры визуальной модели в расчёте не участвуют. Проверяется только участок, который клинок действительно прошёл между предыдущим и текущим physics tick.

`hit_targets` запоминает уже задетые объекты: один враг получает урон только один раз за замах, даже если клинок пересекает его несколько кадров. `point_in_sweep()` оставлен как вспомогательная проверка полной дуги.

Для снарядов из `WorldState.enemy_projectile_snapshot()` к радиусу прибавляется `7.0`: это допуск для надёжного отбивания быстро летящей стрелы. Дальность удара по обычным врагам при этом не меняется.

`_hit_groups_between()` проверяет три типизированных реестра на каждом участке движения клинка:

- `WorldState.enemy_snapshot()` вызывает `take_damage()`;
- `WorldState.enemy_projectile_snapshot()` вызывает `destroy_by_sword()`;
- `WorldState.destructible_snapshot()` вызывает `hit_by_sword()`.

`upgrade_sword()` увеличивает длину, урон и уровень модели меча только до `MAX_SWORD_TIER = 6`. Особый бонус двуручного меча применяется один раз при переходе с уровня `5` на `6`. После этого `can_upgrade_sword()` возвращает `false`, и кнопка меча исчезает из следующих панелей. Если меняете стартовые параметры, обновите их также в `reset()`.

Все три исходных списка закрыты внутри `WorldState` и обновляются при создании и `tree_exiting` объектов. `PlayerAttack` не выполняет поиск групп ни при начале, ни на кадрах замаха.

### `scripts/player/player_magic.gd`

Отдельный модуль магии героя. Правая кнопка мыши вызывает `try_cast()`. Пока заклинание не выбрано при повышении уровня, нажатие ничего не делает.

- `spell_levels` хранит независимые уровни молнии и фаербола;
- `active_spell` хранит выбранное в данный момент заклинание;
- `unlock_or_upgrade()` открывает заклинание или повышает его уровень, а затем делает активным;
- `MAX_SPELL_LEVEL = 6` ограничивает развитие каждой магии;
- `can_upgrade_spell()` сообщает очереди улучшений, нужно ли ещё показывать соответствующую кнопку;
- `try_cast()` рассчитывает урон и перезарядку и испускает сигнал `cast_requested`;
- `reset()` очищает оба уровня в начале нового забега.

Молния начинает с урона `30`, перезарядки `0.68` секунды и получает `+8` урона за уровень. Фаербол начинает с урона `42`, перезарядки `0.95` секунды и получает `+11` урона за уровень. Повышение уровня также немного ускоряет повторное применение.

## Противники

### `scripts/enemies/enemy_base.gd`

Базовый класс всех врагов. Конкретные типы наследуются от него.

Общие параметры:

- `visual_radius` — размер модели в `EnemyVisual`;
- `collision_radius` — независимый радиус Hurtbox для боевых расчётов;
- `max_health` и `health` — здоровье;
- `move_speed` — скорость;
- `contact_damage` — урон атаки;
- `experience_value` — выдаваемый опыт;
- `enemy_kind` — `StringName`-идентификатор из `GameIds`;
- `world_limit` — граница перемещения, переданная из локации.

`setup()` принимает игрока, позицию, сложность и размер карты. Здоровье умножается на `difficulty`, скорость и урон растут мягче.

Основные методы:

- `_physics_process()` вызывает индивидуальный `tick_behavior()` с фиксированным шагом;
- `move_toward_player()` реализует стандартное движение к герою;
- `take_damage()` получает урон, применяет отбрасывание и испускает сигнал `died`;
- `damage_player()` передаёт урон герою;
- `draw_health_bar()` рисует полоску повреждённому врагу.

Не помещайте индивидуальную логику конкретного врага сюда, если она не должна применяться ко всем типам.

Общий визуальный компонент, подключённый к `VisualRoot` каждой сцены врага. ## Снаряды

### `scripts/combat/attack_shape.gd`

Чистая world-space геометрия ближней атаки. `AttackShape` наследует `RefCounted`, не обращается к сцене, камере, `CanvasItem` или `IsoMath` и проверяет swept-сектор против круглой цели. Такой контракт можно вызывать в headless-сервере или заменить двумерную визуализацию на 2.5D, не переписывая правила попаданий.

### `scripts/combat/deflectable_projectile.gd`

Небольшой типизированный контракт для всех вражеских снарядов, которые можно сбить мечом. Он гарантирует наличие `world_position`, независимых `visual_radius`/`collision_radius` и метода `destroy_by_sword()`.

### `scripts/combat/enemy_projectile.gd`

Небольшая красная стрела, выпускаемая стрелком. Направление модели рассчитывается из `velocity`, поэтому наконечник всегда смотрит по ходу полёта.

Параметры:

- `damage = 12.0` — значение по умолчанию, но стрелок передаёт своё при создании;
- `visual_radius = 20.0` — длина визуальной модели стрелы;
- `collision_radius = 14.0` — область столкновения и отбивания мечом;
- `lifetime = 6.0` — время до автоматического удаления;
- `280.0` в `setup()` — скорость полёта.

Унаследованный `destroy_by_sword()` удаляет стрелу, когда она попала в сектор меча. В `PlayerAttack` для стрел дополнительно применяется допуск `7.0`, поэтому их можно уверенно отбивать краем клинка. Модель древка, наконечника и оперения находится в `_draw()`.

Все снаряды движутся в `_physics_process()`. Столкновение проверяется между предыдущей и новой мировой позицией через `CollisionMath`, а магия героя при нескольких пересечениях выбирает ближайшую цель на траектории.

### `scripts/combat/player_magic_projectile.gd`

Снаряд выбранной магии героя. Добавляется в группу `player_magic_projectile` только для редкой очистки забега, а цели проверяет через `WorldState.enemy_snapshot()`. Фаербол получает отдельный snapshot перед AoE, поэтому массовая смерть не изменяет обходимую коллекцию. Полный поиск группы `enemy` каждый кадр не выполняется.

- молния — вытянутый синий разряд, стартовая скорость `520`, прямой урон одной цели;
- фаербол — красный круглый снаряд, стартовая скорость `330`, после попадания наносит урон всем врагам в радиусе `82`;
- уровень увеличивает скорость/размер молнии и радиус взрыва фаербола;
- модель обоих заклинаний полностью находится в `_draw()`.

### `scripts/combat/enemy_spell_projectile.gd`

Вражеская версия заклинаний. Молния летит со скоростью `390`, фаербол — `255`. Оба типа реализуют контракт `DeflectableProjectile`, поэтому существующая зона меча распознаёт их так же, как стрелы, и вызывает `destroy_by_sword()`.

Здесь можно отдельно изменить скорость, радиус столкновения, цвет и форму вражеских заклинаний, не затрагивая магию героя.

## Локация

### `scripts/world/location.gd`

Создаёт пол, границы и случайные объекты.

Настраиваемые параметры:

- `world_limit` берётся из `resources/world_config.tres`;
- `tile_size = 180.0` остаётся локальным размером плиток.

`regenerate()` немедленно убирает старые объекты из дерева и создаёт новые как прямых детей общего `WorldRoot`. Благодаря этому кусты, бочки и деревья участвуют в одной Y-сортировке с героем, врагами и предметами. Текущий состав:

```gdscript
_generate_kind(GameIds.PROP_BUSH, 120)
_generate_kind(GameIds.PROP_BARREL, 64)
_generate_kind(GameIds.PROP_TREE, 46)
```

Меняйте второе число для изменения количества. В `_generate_kind()`:

- `prop_player_clear_radius` — свободная область вокруг старта героя;
- `prop_minimum_spacing` — минимальное расстояние между объектами;
- `prop_edge_margin` — отступ от края карты.

`_draw()` строит двухцветный изометрический пол и золотую границу. Цвета плиток — `171310` и `211913`.

`_generate_kind()` сохраняет исходное требуемое количество и заранее рассчитывает `max_attempts`, поэтому уменьшение `count` больше не сокращает доступный лимит попыток. `WorldConfig.world_limit` является единым источником размера для локации, героя, врагов и алгоритма появления.

### `scripts/world/world_prop.gd`

Описывает куст, бочку и дерево.

`setup()` выбирает тип:

- `tree` — радиус `44`, неразрушаемый;
- `barrel` — радиус `25`, разрушаемый;
- `bush` — радиус `30`, разрушаемый.

`hit_by_sword()` удаляет разрушаемый объект и может запросить бутылку:

- бочка — шанс `0.42`;
- куст — шанс `0.20`.

`_draw()` содержит отдельные ветки отрисовки каждого объекта. Для нового вида добавьте его параметры в `setup()`, новую ветку в `_draw()` и вызов генерации в `location.gd`.

## Предметы

### `scripts/items/pickup.gd`

Один класс для опыта и лечебной бутылки. Тип задаётся `StringName` из `GameIds`.

Опыт:

- начинает магнититься на дистанции меча плюс `pickup_magnet_extra_range`;
- скорость и плавность задаются параметрами группы `Experience Magnet` в `world_config.tres`;
- при подборе вызывает `player.add_experience(value)`.

Бутылка:

- не магнитится;
- при подборе вызывает `player.heal(value)`;
- сила лечения передаётся из `_spawn_potion()` файла `main.gd`.

Размер подбора задаёт `collision_radius = 10.0`, а рисунка — `visual_radius`. Магнит и подбор обновляются в `_physics_process()`. После движения предмет повторно рассчитывает дистанцию до игрока, поэтому быстрый опыт подбирается в тот же physics tick, когда достигает героя.

## Волны

### `scripts/systems/wave_manager.gd`

Управляет временем, частотой появления и составом волн. Таймеры обновляются в `_physics_process()`, поэтому скорость волн не зависит от частоты отрисовки.

- `wave_duration` из `world_config.tres` — продолжительность одной волны;
- `spawn_time` — время до следующего врага;
- `spawn_index` — позиция в гарантированном списке типов;
- `max_active_enemies` из `world_config.tres` — предел одновременно существующих врагов;
- `CombatPhase.WAVES` и `CombatPhase.BOSS` разделяют обычные волны и бой с боссом;
- после волны `7` менеджер переходит в фазу `BOSS`, испускает `combat_phase_changed`, а затем `boss_requested`.

Частота появления рассчитывается так:

```gdscript
maxf(
    world_config.minimum_spawn_delay,
    world_config.base_spawn_delay
        - float(wave) * world_config.spawn_delay_reduction_per_wave
)
```

Все три значения редактируются в группе `Waves` ресурса `world_config.tres`. Рост сложности за волну задаёт `difficulty_growth_per_wave`.

Состав задаётся массивами в `_choose_enemy()`:

- волна 1 — серые бойцы, мечники и стрелки;
- волна 2 — добавляются копейщики и первый маг молнии;
- волны 3–4 — маг молнии чередуется с обычными типами;
- волны 5–7 — дополнительно появляется маг фаербола.

Состав использует константы `GameIds.ENEMY_*`; соответствующая сцена должна присутствовать в словаре `enemy_scenes` файла `main.gd`.

Сложность врага передаётся формулой `1.0 + (wave - 1) * 0.13`. Увеличьте `0.13`, чтобы здоровье и урон врагов росли быстрее.

## Интерфейс

### `scripts/ui/game_ui.gd`

Создаёт интерфейс кодом, без отдельных `.tscn`-панелей.

- `_build_menu()` — главное меню, заголовок и кнопка старта;
- `_build_hud()` — здоровье, опыт, волна, уровень и активное заклинание;
- `_build_upgrade_panel()` — три обычных усиления и две магии; недоступные варианты скрываются при каждом показе;
- `_build_game_over_panel()` — победа или поражение;
- `_button()` — общие параметры всех кнопок;
- `_panel_color()` — фоновый цвет панелей;
- `set_health()`, `set_experience()`, `set_wave()`, `set_magic()` — обновление HUD;
- `CombatDisplayState.WAVES` и `CombatDisplayState.BOSS` хранят отдельное состояние отображения боя;
- `set_boss_state()` показывает надпись `БОСС` вместо фиктивной восьмой волны и выделяет её красным цветом.

Если герой получает достаточно опыта сразу для нескольких уровней, `main.gd` увеличивает `pending_level_ups`. Игра остаётся на паузе, пока игрок последовательно не сделает один выбор за каждый накопленный уровень. Перед каждой следующей панелью доступность кнопок рассчитывается заново, а микро-задержка ввода запускается повторно.

HUD состоит из четырёх `MarginContainer`: `TopLeftContainer`, `TopRightContainer`, `BottomLeftContainer` и `BottomRightContainer`. Они привязаны anchors к соответствующим углам, поэтому сохраняют отступы при 1280×720, 1920×1080 и широком окне. Для текста меняйте свойство `text`, для отступов — `offset_*`; размер шрифта задаётся через `add_theme_font_size_override()`.

Если интерфейс станет сложнее, рекомендуется вынести его в отдельную сцену `scenes/ui/game_ui.tscn`, а в этом скрипте оставить только обновление данных.

## Служебные `.uid`-файлы

Рядом с каждым `.gd` Godot создаёт файл вида `player.gd.uid`.

Они нужны движку для устойчивых ссылок на ресурсы. Их следует хранить в Git, но не нужно открывать или редактировать вручную. Если удалить `.uid`, Godot создаст новый, из-за чего ссылки в сценах могут измениться.

## Как добавить нового противника

Пример: новый быстрый фиолетовый враг.

1. Скопируйте `scripts/enemies/melee_enemy.gd` в `scripts/enemies/fast_enemy.gd`.
2. Поменяйте `class_name` на `FastEnemy`.
3. В `scripts/core/game_ids.gd` добавьте `const ENEMY_FAST := &"fast"`.
4. В `_init()` задайте `enemy_kind = GameIds.ENEMY_FAST` и характеристики.
5. Измените `tick_behavior()` для нового поведения.
6. Измените `_draw()` для другой модели и цвета.
7. Скопируйте сцену `scenes/enemies/melee_enemy.tscn` в `fast_enemy.tscn`.
8. Подключите в новой сцене `fast_enemy.gd`.
9. В `scripts/main.gd` добавьте:

```gdscript
const FAST_ENEMY_SCENE := preload("res://scenes/enemies/fast_enemy.tscn")
```

10. В словарь `enemy_scenes` добавьте:

```gdscript
GameIds.ENEMY_FAST: FAST_ENEMY_SCENE,
```

11. Добавьте `GameIds.ENEMY_FAST` в нужный массив файла `wave_manager.gd`.
12. Запустите проверку Godot и убедитесь, что новый тип появляется.

## Как добавить новое улучшение уровня

1. Добавьте кнопку в `_build_upgrade_panel()` файла `game_ui.gd`.
2. Передайте новый `StringName`-идентификатор через `upgrade_selected`.
3. Добавьте ветку в `_apply_upgrade()` файла `main.gd`.
4. Добавьте условие доступности в `available_upgrade_choices()` файла `main.gd`.
5. Реализуйте отдельный метод изменения параметров в том модуле, которому принадлежит улучшение.

Например, усиление скорости снарядов противника должно находиться в системе противников или снарядов, а не в UI.

## Как добавить новое заклинание

1. Добавьте его начальный уровень в `spell_levels` файла `player_magic.gd`.
2. Добавьте расчёт урона и перезарядки в `PlayerMagic.try_cast()`.
3. Добавьте скорость, радиус попадания и время жизни в `PlayerMagicProjectile.setup()`.
4. Нарисуйте новую модель в `PlayerMagicProjectile._draw()` и добавьте нужный эффект в `_impact()`.
5. Добавьте кнопку с тем же строковым идентификатором в `_build_upgrade_panel()`.
6. Если заклинанием должен пользоваться враг, добавьте его модель в `EnemySpellProjectile` и настройте `spell_kind` в новом наследнике `MageEnemyBase`.

Идентификатор должен быть одной константой `GameIds`: например, для молнии везде используется `GameIds.SPELL_LIGHTNING`.

## Как добавить новый объект карты

1. Создайте `PropDefinition` в `resources/content/props/`.
2. Укажите `id`, количество, визуальный и боевой радиусы, разрушаемость и шанс лечебной бутылки.
3. Добавьте ресурс в массив `props` файла `resources/game_content.tres`.
4. Если объекту нужен новый внешний вид, добавьте только ветку отрисовки в `WorldProp._draw()`.

## Data-driven контент

Главный каталог находится в `resources/game_content.tres`. Он содержит типизированные ресурсы:

- `EnemyDefinition` — сцена врага, размеры, здоровье, скорость, урон, опыт, дистанция появления и признак босса;
- `SpellDefinition` — урон, перезарядка, скорость, радиусы, время жизни и масштабирование по уровням;
- `WeaponDefinition` — предел уровня меча, длина, ширина зоны удара, урон и длительность взмаха;
- `UpgradeDefinition` — текст кнопки, ID улучшения и связь с заклинанием;
- `WaveDefinition` — состав волны, необязательная длительность и босс после волны;
- `PropDefinition` — количество объектов, размеры, разрушаемость и шанс лечебной бутылки.

### Как добавить нового врага без изменения `main.gd`

1. Создайте сцену врага на основе `EnemyBase` или одного из его наследников.
2. Создайте новый `.tres` в `resources/content/enemies/`, назначьте уникальный `id`, сцену и характеристики.
3. Добавьте этот ресурс в массив `enemies` файла `resources/game_content.tres`.
4. Добавьте его `id` в `enemy_roster` нужного `WaveDefinition` в `resources/content/waves/`.

`GameMain._spawn_enemy()` получает сцену и характеристики через `GameContent.enemy(id)`, поэтому список конкретных врагов в `main.gd` отсутствует. Повторяющиеся ID в `enemy_roster` увеличивают относительную частоту появления врага.

## Проверка после изменений

В Godot:

1. Откройте проект и дождитесь завершения импорта.
2. Проверьте панель **Output** на ошибки `Parse Error` и `Invalid call`.
3. Запустите главную сцену.
4. Начните забег и проверьте изменённую механику.

Безоконная проверка из терминала:

```powershell
Godot_v4.7.1-stable_win64.exe --headless --editor --path . --quit
Godot_v4.7.1-stable_win64.exe --headless --path . --quit-after 3
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_fireball_registry.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_fixed_tick_collision.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_level_up_queue.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_entity_scenes.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_world_space_combat.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_data_driven_content.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_spatial_index.gd
```

Первая команда компилирует и импортирует проект. Вторая кратко запускает главную сцену. Остальные проверяют массовое AoE, physics-таймеры, очередь повышений, структуру entity-сцен, независимую world-space геометрию боя и универсальный спавн врага из каталога.

## Пространственный индекс

`SpatialGrid` делит world-space на квадратные ячейки. `WorldState` хранит в отдельных сетках врагов, вражеские снаряды, разрушаемые цели и все препятствия. Меч, магические снаряды и AoE сначала запрашивают только соседние ячейки, а точную геометрию проверяют уже на небольшой локальной выборке.

Размер ячейки, параметры separation, свободный зазор спавна и лимиты временных объектов находятся в `resources/world_config.tres`. Враги и игрок используют сетку для обнаружения препятствий; при заблокированном диагональном движении сначала пробуется скольжение по каждой оси. Точка появления врага отклоняется, если пересекает героя, другого врага или объект карты.

## CI и Web-сборка

Workflow `.github/workflows/godot-ci.yml` запускается для push, pull request и вручную через `workflow_dispatch`. Он выполняет следующие этапы:

1. Скачивает Godot 4.7.1 и соответствующие Web export templates.
2. Импортирует проект и компилирует GDScript в headless-режиме.
3. Запускает проверку ресурсов и отсутствующих `res://`-файлов.
4. Выполняет все автоматические тесты.
5. Создаёт главную сцену и держит её несколько physics-кадров для smoke test.
6. Экспортирует preset `Web` в `builds/web/`.
7. Проверяет наличие HTML, PCK и WASM, после чего загружает папку как GitHub Actions artifact.

Артефакт получает имя `circle-raider-web-<commit SHA>` и хранится 14 дней. В Web-export не включается каталог `tests/`.

Локальные проверки новых CI-контрактов:

```powershell
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_resource_validation.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --script res://tests/test_smoke.gd
Godot_v4.7.1-stable_win64.exe --headless --path . --export-pack Web "$env:TEMP/testgame-web-check.pck"
```

Для полного локального HTML-экспорта должны быть установлены Web export templates той же версии Godot:

```powershell
Godot_v4.7.1-stable_win64.exe --headless --path . --export-release Web builds/web/index.html
```

## Безопасная работа с Git

Перед изменениями убедитесь, что выбрана ветка `godot-port`.

Рекомендуемый порядок:

```text
1. Изменить один модуль.
2. Запустить проект.
3. Проверить связанную механику.
4. Сделать отдельный коммит с понятным названием.
```

Не добавляйте в Git папку `.godot/`: это локальный кэш. Не удаляйте `.gd.uid`. Браузерную версию изменяйте отдельно в ветке `circle-raider`.
